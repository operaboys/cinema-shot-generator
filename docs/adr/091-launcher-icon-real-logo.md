# ADR-091: آیکون اصلی اپ (Launcher) با نشان واقعی Aperture C (یافته‌ی #۸ appendix، تکمیل نهایی)

## زمینه

`ic_launcher_foreground.xml` یک Placeholder موقت بود (دایره‌ی زرد ساده،
کامنت صریح خودِ فایل: «دایره‌ی ساده به‌عنوان آیکون موقت (لنز دوربین)»). طبق
ADR-090، محل‌های تعویض‌شده‌ی نشان واقعی صراحتاً آیکون Launcher را کنار
گذاشتند (ریسک بصری Safe Zone نیازمند بررسی جدا). این قدم همان بررسی را با
تأیید صریح کاربر انجام داد.

## ریسک Safe Zone — بررسی و رفع

Adaptive Icon اندروید فقط ناحیه‌ی مرکزی ۶۶×۶۶dp از کل بوم ۱۰۸×۱۰۸dp را
تضمین می‌کند (نیم‌قطر ایمن = ۳۳dp)؛ محتوای بیرون آن ممکن است زیر ماسک‌های
تهاجمی‌تر (مثلاً دایره‌ی کامل) بریده شود.

- **شعاع واقعی طرح**: با نمونه‌برداری مستقیم ۵۰۰ نقطه روی هر Segment واقعی
  (نه صرفاً گوشه‌های bbox — یافته‌ی دیباگ این قدم: بررسی اول با گوشه‌های bbox
  عدد غلط ۱۲۹.۷۴ داد، چون گوشه‌های کادر محیطی الزاماً روی خودِ شکل نیستند)
  با `svgpathtools`، شعاع بیرونی واقعی طرح دقیقاً **۱۰۴ واحد** در فضای محلی
  SVG اصلی تأیید شد (منطبق با شعاع Arc بیرونی خودِ مسیرها).
- **Scale**: `32 / 104 ≈ 0.3077` — کمی کوچک‌تر از نیم‌قطر ایمن ۳۳dp، برای
  حاشیه‌ی اطمینان ۱dp. روی مختصات پایانی هر Arc/Line **و** شعاع هر Arc اعمال
  شد، سپس به مرکز Viewport ۱۰۸×۱۰۸ (۵۴,۵۴) منتقل شد.
- **تأیید بصری واقعی**: طرح تولیدشده به یک SVG معادل تبدیل و با
  `rsvg-convert` رندر شد — هم با دایره‌ی راهنمای Safe Zone روی طرح کامل، هم
  زیر یک ماسک دایره‌ای کامل واقعی (تهاجمی‌ترین شکل استاندارد) در ۹۶dp و
  ۴۸dp. نتیجه: بدون هیچ بریدگی، طرح کامل داخل Safe Zone جا می‌شود، حتی در
  اندازه‌ی کوچک ۴۸dp خوانا می‌ماند.

## رنگ پس‌زمینه (`ic_launcher_background`، #1A1A2E) — بررسی و تصمیم: دست‌نخورده ماند

کنتراست واقعی WCAG هر ۹ رنگ گرادیان طرح در برابر #1A1A2E محاسبه شد (فرمول
luminance رسمی، نه حدس):

| رنگ | کنتراست در برابر #1A1A2E |
|---|---|
| نارنجی روشن #FFB65E | ۹.۸۳:۱ |
| بنفش روشن‌ترین #C2ACFF | ۸.۶۴:۱ |
| نارنجی #F0821F | ۶.۴۳:۱ |
| بنفش روشن #A98CFF | ۶.۴۰:۱ |
| نارنجی تیره #E07A22 | ۵.۶۷:۱ |
| بنفش میانی #8A6BFF | ۴.۵۷:۱ |
| بنفش میانی #7C5CFF | ۳.۹۲:۱ |
| بنفش تیره #5B3ED6 | ۲.۵۲:۱ |
| بنفش تیره‌ترین #4C31C4 | ۲.۰۷:۱ |

**تصمیم**: تغییر نکرد. ۶ از ۹ رنگ ≥۴.۵:۱ (معیار AA متن معمولی)، شامل هر دو
انتهای طیف گرادیان (نارنجی‌ترین و بنفش‌روشن‌ترین). فقط تیره‌ترین لبه‌های بنفش
(که خودِ گرادیان اپ عمداً به‌سمت تیرگی می‌رود) کنتراست کمتری دارند — رفتار
طبیعی یک گرادیان گرم-به-سرد، نه نقص طراحی؛ تأیید بصری رندرشده (بالا) هم این
را نشان داد — طرح کاملاً خوانا و متمایز از پس‌زمینه است. این رنگ همان
پس‌زمینه‌ی اصلی تم تیره‌ی کل اپ است (نه یک انتخاب اختصاصی Launcher)، طبق
دستور کار این قدم («اگر کار کرد دست‌نخورده بماند») دست‌نخورده ماند.

## پیاده‌سازی

`ic_launcher_foreground.xml` با نسخه‌ی Scale‌شده (بالا) جایگزین شد — همان ۸
Path/Gradient `ic_aperture_c_logo.xml` (ADR-090)، نه یک ارجاع مستقیم بدون
تنظیم (که لبه‌های طرح را زیر ماسک‌های تهاجمی می‌برید). `mipmap-anydpi-v26/
ic_launcher.xml` و `colors.xml` بدون تغییر ماندند.

## تست

بدون تست تازه (طبق دستور کار — تغییر بصری خالص Launcher). `assembleDebug`
تأیید کرد XML معتبر است (aapt2 با موفقیت پردازش کرد). تأیید بصری با
`rsvg-convert` (بالا) به‌عنوان راستی‌آزمایی مکمل انجام شد، نه بخشی از Test
Suite خودکار.
