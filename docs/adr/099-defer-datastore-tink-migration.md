# ADR-099: تصمیم آگاهانه — عدم مهاجرت به androidx.datastore:datastore-tink (فعلاً)

**نوع:** مستندسازی صرف — هیچ کد/منطقی در این قدم تغییر نکرد.

## زمینه

ADR-098 (G2 قدم ۱ از ۳) دو یافته را گزارش کرد:

1. `androidx.security.crypto` از نسخه‌ی `1.1.0-beta01` به بعد Deprecated
   است — گوگل «استفاده‌ی مستقیم از Android Keystore» را به‌عنوان جایگزین
   معرفی کرده.
2. با جست‌وجوی مستقل بیشتر (این قدم) مشخص شد گوگل جایگزین رسمی مشخصی هم
   منتشر کرده: `androidx.datastore:datastore-tink` — اولین انتشار آن
   (نسخه‌ی `1.3.0-alpha07`) در ۱۱ آوریل ۲۰۲۶ عرضه شد.

## بررسی

این کتابخانه هنوز در همان اولین انتشار **Alpha** است — نه Beta، نه Release
Candidate، نه Stable. طبق قرارداد نسخه‌گذاری androidx (semver با پیشوند
`alpha`/`beta`/`rc`)، نسخه‌های Alpha هیچ تضمین پایداری API ندارند؛ حتی
نویسنده‌های متخصص حوزه‌ی امنیت Android صراحتاً هشدار داده‌اند API این
کتابخانه ممکن است در نسخه‌های بعدی به‌شدت تغییر کند (Breaking Changes بدون
مسیر Migration رسمی).

## تصمیم

**فعلاً روی `androidx.security.crypto:1.1.0` باقی می‌مانیم** — پایدار،
منتشرشده، کاملاً کارکردی (تأییدشده با تست واقعی در ADR-098)، فقط Deprecated
از نظر توصیه‌ی آینده‌ی گوگل، نه شکسته یا حذف‌شده. مهاجرت به
`datastore-tink` به یک قدم آینده موکول می‌شود.

**دلیل (ریسک در برابر فایده):** این پروژه یک MVP شخصی در حال توسعه است. هزینه‌ی
واقعی وابستگی به یک کتابخانه‌ی Alpha (که طبق هشدار صریح متخصصان ممکن است
دوباره API را بشکند و کد را مجبور به بازنویسی کند) بزرگ‌تر از هزینه‌ی
نگه‌داشتن یک هشدار Deprecation بی‌ضرر روی یک کتابخانه‌ی پایدار و کارکردی
است. فرار زودهنگام از Deprecation با پرش به یک Alpha، ریسک واقعی (شکستن
مجدد کد در آینده‌ی نزدیک) را با یک فایده‌ی صرفاً نمادین (سکوت هشدار
کامپایلر) معاوضه می‌کرد — معاوضه‌ی نامتوازن برای این مرحله از پروژه.

## شرط بازبینی (قابل‌پیگیری)

این تصمیم باید بازبینی شود وقتی `androidx.datastore:datastore-tink` به
نسخه‌ی **Stable یا حداقل Release Candidate** برسد (نه Alpha/Beta) — طبق
همان معیاری که این تصمیم را توجیه کرد (پایداری API).

ثبت‌شده به‌عنوان **R6** در `docs/governance/risk-register.md` — همان محل
موجود پروژه برای پیگیری بدهی‌های معماری مشابه با «وضعیت» زنده (نه یک فایل
جدید مجزا؛ پروژه از قبل چنین ساختاری برای دقیقاً همین نوع تصمیم دارد، طبق
R4/R5 موجود در همان فایل).


`SecureKeyRepository.kt`: یک خط ارجاع کوتاه به همین ADR اضافه شد (بدون
تغییر منطق/کد) — کامنت موجود که به وضعیت Deprecated اشاره می‌کرد اکنون
صریحاً می‌گوید چرا مهاجرت هنوز انجام نشده.

هیچ فایل `.kt` دیگری، `build.gradle.kts`، یا `libs.versions.toml` تغییر
نکرد — این قدم صرفاً یک تصمیم از‌قبل‌گرفته‌شده‌ی عملی (چون کد از ADR-098 با
`security.crypto` نوشته شده بود) را رسمی و قابل‌پیگیری مستند می‌کند.
