### ۱. بدون تغییر هویت پروژه
Claude Code هرگز نمی‌تواند DNA پروژه را تغییر دهد، هویت سبک را از نو تعریف کند، یا جهت خلاقانه‌ی جدیدی معرفی کند. هویت پروژه فقط توسط کاربر (انسان) قفل/تغییر می‌شود.

```python
# ❌ نقض
def auto_improve_style():
    dna.visual_style = "anime"  # تصمیم مستقل AI برای تغییر هویت

# ✅ مجاز
def suggest_style_change():
    return "Consider anime style for this project"  # فقط پیشنهاد
```

### ۲. بدون تصمیم ضمنی — با یک تفکیک مهم
دو نوع داده وجود دارد:

- **داده‌ی الزامی/ساختاری** (بدون آن پرامپت بی‌معنی است — مثل Shot بدون توضیح): هرگز حدس نزن؛ متوقف شو و بپرس.
- **جزئیات قابل‌استنباط از Context** (مثل انتخاب لباس بر اساس آب‌وهوا): پیش‌فرض خودکار مجاز است، **به‌شرطی که** منطق شفاف و قابل‌ردیابی باشد، کاربر بتواند دستی Override کند، و این استنباط ثبت شود.

```python
# ❌ نقض (داده‌ی الزامی حدس زده شده)
def process_shot(shot):
    if shot.description is None:
        shot.description = "a shot"  # ممنوع

# ✅ مجاز (استنباط شفاف از جزئیات قابل‌استنباط)
def infer_character_outfit(character, scene):
    if character.outfit_override is not None:
        return character.outfit_override
    if scene.weather == "rainy" and character.has_variant("rain_outfit"):
        return character.get_variant("rain_outfit")
    return character.default_outfit
```

### ۳. بدون بهینه‌سازی خودخواسته
بهینه‌سازی فقط وقتی مجاز است که صریحاً درخواست شده، محدوده‌اش مشخص باشد، و رفتار سیستم را تغییر ندهد. بهینه‌سازی بی‌صدا ممنوع است.

### ۴. بدون نشتِ مسئولیت بین واحدهای معماری
Claude Code باید مرز واحدهای معماری (طبق `module-boundaries.md`) را محترم بشمارد — منطق یک واحد را در واحد دیگر تکرار یا جابه‌جا نکند.

```python
# ❌ نقض — تکرار منطق Validation در یک واحد دیگر
def validate_in_ui_layer(shot):
    if shot.duration > 60:  # این منطق متعلق به Validation Engine است
        return False

# ✅ مجاز — استفاده از واحد صاحب مسئولیت
def validate_in_ui_layer(shot):
    return validation_engine.validate_shot(shot)
```

### ۵. بدون حافظه‌ی ضمنی از تصمیمات گذشته
Claude Code نباید ترجیحات کاربر را از خروجی‌های قبلی حدس بزند یا فرض تداوم سلیقه بسازد. فقط Context صریح ارائه‌شده در همان لحظه معتبر است.

### ۶. ردیابی‌پذیری الزامی
هر اقدام باید قابل توضیح، قابل ردیابی به یک درخواست مشخص، و قابل بازگشت باشد. اگر توضیح واضحی برای یک تغییر وجود ندارد، آن تغییر نامعتبر است.

### ۷. اعتبارسنجی اجباری
Claude Code همیشه باید از لایه‌ی Validation عبور کند و سیگنال‌های رد را محترم بشمارد. Bypass کردن Validation برای سرعت ممنوع است.

### ۸. بدون بازنویسی خودخواسته
Refactor گسترده (تغییر نام سراسری، بازسازماندهی معماری) بدون تأیید صریح انسان ممنوع است. پیشنهاد بده، خودسرانه اجرا نکن.

### ۹. خطا بهتر از حدس — با همان تفکیک Guardrail ۲
برای داده‌ی الزامی/ساختاری: خطا > حدس، توقف > ادامه، پرسیدن > فرض کردن. برای جزئیات قابل‌استنباط: استنباط با منطق شفاف و امکان Override مجاز است؛ حدسِ بدون منطق مشخص هنوز ممنوع است.

### ۱۰. پایداری بر خلاقیت
وقتی مجبور به انتخاب هستی: پیش‌بینی‌پذیری بر هوشمندی، پایداری بر نوآوری، وضوح بر اختصار.

```python
# ❌ نقض — هوشمندانه ولی غیرقابل‌پیش‌بینی
def process(x):
    return eval(magic_transform(x))

# ✅ مجاز — ساده و پایدار
def process(x):
    if x.type == "A":
        return process_a(x)
    elif x.type == "B":
        return process_b(x)
    else:
        raise ValueError(f"Unknown type: {x.type}")
```

## قاعده‌ی ایمنی (Fail-Safe Rule)

اگر یک اقدام می‌تواند رفتار سیستم را تغییر دهد، هویت خروجی را تغییر دهد، یا پایداری بلندمدت را تحت‌تأثیر قرار دهد — آن اقدام به‌طور پیش‌فرض **مسدود** است.

**در شک، مسدود کن.**

## دامنه‌ی تصمیم‌گیری

**Claude Code می‌تواند خودش تصمیم بگیرد:** نحو کد، فرمت، جزئیات پیاده‌سازی محلی (انتخاب ساختار داده، الگوریتم داخلی یک تابع)، بهینه‌سازی محلی بدون تغییر رفتار بیرونی.

**Claude Code نمی‌تواند خودش تصمیم بگیرد:** رفتار کلی سیستم، اولویت قوانین معماری (مثل ترتیب Human Override > Shot > Scene > DNA)، الگوهای معماری سطح بالا، تغییر Schema اصلی.
