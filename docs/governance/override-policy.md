# سیاست Human-in-the-Loop و Override

**نقش:** Governance — قانون رفتاری سیستم (نه بلوپرینت یک واحد اجرایی)
**وضعیت:** فعال

---

## فلسفه‌ی اصلی: Human-AI Collaboration

```
انسان = معمار / کارگردان / تصمیم‌گیر نهایی
AI    = اجراکننده / پیشنهاددهنده / تحلیل‌گر / دستیار
```

**قانون طلایی:** AI هیچ‌گاه جای انسان تصمیم نهایی نمی‌گیرد.

این سیستم بدون انسان ناقص است؛ بدون AI کند است. ترکیب این دو هدف اصلی پروژه است.

---

## دو context متفاوت — این تمایز حیاتی است

این سند دو لایه‌ی کاملاً جدا را پوشش می‌دهد که نباید با هم اشتباه گرفته شوند:

### ۱. حاکمیت توسعه (بین معمار انسانی و Claude Code)
وقتی در حین *ساخت و توسعه‌ی این اپ* یک بررسی معماری انجام می‌شود، Claude Code نباید خودش مستقل و خودکار تصمیم نهایی بگیرد؛ باید به بازبینی معمار پروژه ارجاع دهد. **Validation در این context صرفاً مشورتی (Advisory) است** — سیگنال و هشدار می‌دهد، اما به‌تنهایی مانع اجرا نمی‌شود. تنها زمانی‌که سیگنال‌های اعتبارسنجی با هم تناقض دارند، یا Red Flag/Anti-Pattern فعال می‌شود، یا یک تغییر معماری بزرگ بعد از قفل‌شدن پیشنهاد می‌شود، بازبینی انسانی الزامی می‌گردد. در آن حالت، خروجی اعتبارسنجی صرفاً ورودی الزامی برای تصمیم انسانی است، نه یک وتوی خودکار.

### ۲. رفتار محصول نهایی (اپ در دست کاربر)
این context جداست. طبق Validation Engine محصول، برای داده‌ای که بدون آن پرامپت ساختاری بی‌معنی می‌شود (مثل Shot بدون Subject)، سیستم باید واقعاً جلوی ادامه را بگیرد (**Blocking**) — نه فقط هشدار بدهد. این دو اصل با هم در تضاد نیستند؛ فقط به دو موقعیت متفاوت اشاره دارند.

## سطوح دخالت انسان (Human Intervention Levels)

| سطح | Scope | اختیار |
|---|---|---|
| **Project** | کل پروژه | کامل و مطلق — تغییر Vision، Override کامل DNA، تغییر مسیر هنری، قفل/آزادسازی پروژه |
| **Story/Narrative** | ساختار روایت | کامل — تغییر پلات، جابه‌جایی Scene، تغییر Timeline؛ در این سطح حس می‌تواند بر منطق سیستم اولویت داشته باشد |
| **Scene** | یک صحنه کامل | کامل در محدوده‌ی Scene — تغییر Mood، نور، زمان، اتمسفر، مکان، آب‌وهوا |
| **Shot** | یک شات | کامل در محدوده‌ی Shot — Override دوربین، نور، محیط، سوژه |

## Override — قوانین رسمی

### مدل مجوز: دو سطح (نه سلسله‌مراتب اولویت)

Override دیگر سیستم اولویت جداگانه (Low/Medium/High/Absolute) ندارد. تصمیم فقط به severity قانونی که Override می‌شود بستگی دارد:

- **Blocking Rules:** قوانینی که بدون رعایتشان پرامپت ساختاری بی‌معنی می‌شود (مثل Shot بدون Subject) — **اصلاً قابل Override نیستند.**
- **Warning Rules:** قوانین سلیقه‌ای/کیفی (تضاد سبکی، ترکیب غیرمعمول نور و mood، DNA Soft Lock) — **همیشه قابل Override با یک اقدام کاربر.**

### الزامات هر Override

**Scope — الزامی، ثبت خودکار:**
سیستم به‌صورت خودکار ثبت می‌کند چه‌چیزی/کجا/چه‌مقداری تغییر کرد. کاربر نیازی به وارد کردن دستی ندارد.

```json
{
  "scope": {
    "entity_type": "shot",
    "entity_id": "shot_042",
    "field": "camera.angle",
    "original_value": "eye-level",
    "override_value": "dutch-angle"
  }
}
```

**دلیل (Reason) — اختیاری:**
کاربر می‌تواند دلیل را یادداشت کند، ولی سیستم هرگز این فیلد را اجباری نمی‌کند. کاربر تک‌نفره‌ی این پروژه نیازی به Audit Trail رسمی برای خودش ندارد — تاریخچه‌ی کامل نسخه‌ها (چه‌چیزی، در چه زمانی) توسط State & Versioning به‌صورت خودکار حفظ می‌شود.

```json
{
  "justification": { "reason": "برای تأکید روی احساس خشم شخصیت" }
}
```

**بدون Expiration خودکار:**
هیچ Override ای رسماً "Temporary" یا "Permanent" نیست و منقضی نمی‌شود. کاربر هر وقت بخواهد، دستی Override را Revoke می‌کند.

### ساختار کامل یک Override

```json
{
  "override_id": "ovr_042",
  "created_at": "2026-02-06T15:30:00Z",
  "override_type": "artistic" | "narrative" | "visual" | "technical",
  "scope": {
    "entity_type": "shot",
    "entity_id": "shot_042",
    "field": "camera.angle",
    "original_value": "eye-level",
    "override_value": "dutch-angle"
  },
  "justification": { "reason": "برای تأکید روی احساس خشم شخصیت" },
  "status": {
    "active": true,
    "revoked_at": null,
    "revoke_reason": null
  },
  "validation": {
    "conflicts_caused": ["dna_rule_001"],
    "warnings_suppressed": 2
  }
}
```

### چهار نوع Override (دسته‌بندی موضوعی، نه سطح دسترسی)

| نوع | هدف | مثال |
|---|---|---|
| **Artistic** | دستیابی به جلوه‌ی هنری خاص | Dutch Angle برای حس Unease؛ شکستن Continuity برای جلوه‌ی Dreamlike |
| **Narrative** | نیازهای روایی داستان | تغییر موقت Continuity برای Flashback؛ تغییر ظاهر کاراکتر برای نمایش گذر زمان |
| **Visual** | تغییرات فنی بصری | امتحان سبک نورپردازی جدید؛ تست حرکت دوربین غیرمعمول |
| **Technical** | حل مشکل فنی/سیستمی | غیرفعال کردن یک Validation اشتباه؛ تغییر محدودیت طول برای پرامپت بزرگ |

### چرخه‌ی حیات Override

```
ایجاد → فعال → (در صورت طولانی شدن) بررسی مجدد → پایان
                                                   ├─ غیرفعال می‌شود (Revoke دستی توسط کاربر)
                                                   └─ به قانون دائمی سیستم تبدیل می‌شود (در صورت تصمیم آگاهانه)
```

Override حذف نمی‌شود، فقط غیرفعال (Revoked) می‌شود. تاریخچه برای مرور بعدی حفظ می‌گردد.

### هشدارهای سیستم

- **Continuity Break:** این Override باعث شکستن Continuity می‌شود — تأیید می‌کنید؟
- **DNA Violation:** این Override با قوانین DNA در تضاد است — آیا مطمئنید؟
- **High Usage:** در بازه‌ی اخیر Override زیادی ثبت شده — آیا سیستم مشکل دارد؟
- **Long-Active Override:** این Override مدت طولانی است فعال است — ارزش دارد بررسی کنید آیا هنوز لازم است یا باید به قانون دائمی تبدیل شود.

### ریسک‌های شناخته‌شده

- **Override Cascade:** یک Override ممکن است زنجیره‌ای از Override های دیگر را لازم کند.
- **System Bypass:** استفاده‌ی بیش‌ازحد از Override، اعتبار خودِ سیستم قوانین را زیر سؤال می‌برد.
- **Lost Context:** بدون یادداشت دلیل، ممکن است بعد از مدتی دلیل یک Override فراموش شود (به همین دلیل فیلد دلیل، هرچند اختیاری، توصیه می‌شود).
- **Technical Debt:** یک Override موقت ممکن است ناخواسته به بخش دائمی سیستم تبدیل شود — نظارت دوره‌ای لازم است.

## مرزهای تصمیم‌گیری بر اساس وضعیت سیستم (فرآیند توسعه)

| وضعیت سیستم | نقش Validation | دخالت انسانی |
|---|---|---|
| قبل از قفل معماری | مشورتی | اختیاری |
| بعد از قفل، بدون تعارض | مشورتی | تأیید صریح الزامی |
| بعد از قفل، سیگنال‌های متناقض | فعال‌کننده‌ی تشدید بررسی | الزامی |
| Red Flag فعال شد | تشدید فوری | الزامی؛ تصمیم باید صریح، ثبت‌شده و قابل‌ردگیری باشد |

**قیود سراسری:** در هیچ شرایطی Validation به‌تنهایی مرجع نهایی تصمیم نیست؛ تفسیر AI جایگزین تأیید صریح انسانی نمی‌شود؛ خروجی خودکار جای مسئولیت‌پذیری انسانی را نمی‌گیرد.
