# اهداف رد‌شده (Non-Goals)

**نقش:** Governance — قانون رفتاری سیستم
**وضعیت:** فعال

مواردی که عمداً در این پروژه پیاده‌سازی نمی‌شوند. نبود این‌ها «کمبود» نیست، یک تصمیم آگاهانه است.

---

- **تصمیم‌گیری داستانی توسط Prompt Engineering Core** — این واحد فقط داده را ترکیب و تضاد را حل می‌کند، هرگز خودش محتوای داستانی تولید یا تصمیم هنری نمی‌گیرد.
- **اصلاح خروجی در مرحله‌ی Validation** — Validation فقط گزارش می‌دهد چه چیزی نادرست است، هرگز خودش داده را تغییر نمی‌دهد.
- **Override بدون ثبت خودکار Scope** — ثبت این‌که چه‌چیزی/کجا/چه‌زمانی تغییر کرد همیشه اجباری و خودکار است (بخشی از State & Versioning)؛ آنچه اختیاری است فقط «دلیل» است، نه خودِ ثبت تغییر.
- **تغییر هویت پروژه به‌خاطر خروجی‌های مقطعی** — یک تصمیم یا Override موردی نباید باعث تغییر دائمی DNA پروژه شود؛ چنین تغییری باید آگاهانه و صریح باشد.
- **وابستگی مستقیم لایه‌های داخلی به یک مدل یا سرویس خاص** — Prompt Engineering Core و بقیه‌ی منطق اصلی باید کاملاً مستقل از هر مدل AI خاص بمانند؛ فقط Output Delivery System (از طریق Model Profile Library) به جزئیات یک مدل خاص آگاه است.

---

**یادآوری:** اگر وسوسه شدید یکی از این Non-Goal ها را کنار بگذارید، اول دلیل اصلی تصمیم اولیه را دوباره بخوانید — معمولاً همان دلیل هنوز پابرجاست.
